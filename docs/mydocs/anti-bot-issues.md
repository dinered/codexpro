## У-1 — Детектор сопротивления: кандидаты селекторов капчи + редирект на логин

Приоритет: **высокий** · [ишью #1](https://github.com/dinered/codexpro/issues/1)

<!-- тело ишью: скопировать блок ниже -->

**Проблема.** `challenge` — единственный селектор-одиночка в профиле (`selectors/chatgpt.yaml:23`, `[data-testid="challenge"]`), тогда как остальные обязательные элементы — списками кандидатов RU/EN + data-testid. Плюс web-драйвер не распознаёт редирект на вход: тип `restriction` уже есть в `Challenge` (его использует HumanDriver), но ChatGptDriver его не отдаёт.

**Предложение.**
- кандидаты капчи: Turnstile — `iframe[src*="challenges.cloudflare.com"]`, `[data-turnstile-sitekey]`; hCaptcha — `[data-hcaptcha-widget-id]`, `iframe[title*="hCaptcha"]`; интерстишл Cloudflare;
- редирект на логин: домен совпадает, путь `/auth/login` (и подобные) → `kind: "restriction"`;
- мост считает найденным первый ВИДИМый кандидат (как у кнопок, Д-5).

**П-6:** это не обход — раньше останавливаться и с понятной диагностикой в журнале.

**Приёмка.** Контрактные тесты: мост останавливается (BRIDGE_FATAL CHALLENGE) на каждом артефакте; самопроверка не требует необязательных селекторов.

## У-2 — NetworkProbe: сигналы сопротивления 403/429 → остановка моста

Приоритет: **высокий** · [ишью #2](https://github.com/dinered/codexpro/issues/2)

<!-- тело ишью: скопировать блок ниже -->

**Проблема.** Probe слушает только `Network.dataReceived`/`responseReceived` ради idle-признака (`src/driver/cdp-stream.ts:28-29`), хотя в `responseReceived` уже приходит статус ответа. «Невидимая капча» (score-based) не показывает DOM-элемент — но всегда проявляется на транспортном уровне.

**Предложение.** Считать 403/429 на API-эндпоинтах чата (и всплеск 30x на основной домен) сигналом сопротивления → та же ветка, что капча: BRIDGE_FATAL CHALLENGE с явной причиной. Флаг тот же `network_probe` (off по умолчанию). Решение — только «стоп», никогда «адаптация».

**П-6:** детектируем сопротивление → останавливаемся. Это единственный честный ответ на невидимые капчи.

**Приёмка.** Контрактный тест «платформа отвечает 429 → мост остановился с верной причиной»; флаг off — поведение не меняется; detach в finally не ломается.

## У-3 — Опциональный порционный ввод (BRIDGE_INPUT_MODE=instant|chunks)

Приоритет: **средний** · [ишью #3](https://github.com/dinered/codexpro/issues/3)

<!-- тело ишью: скопировать блок ниже -->

**Проблема.** `typeText` вставляет строку мгновенно (`keyboard.insertText`, `src/driver/chatgpt.ts:53`) — события keydown/keyup для символов не генерируются. Это главный поведенческий пробел (аудит anti-bot, таблица §2.2).

**Предложение.** Режим `BRIDGE_INPUT_MODE=instant|chunks` (по умолчанию instant — обратная совместимость). В chunks: вставка/набор порциями (по предложениям), интервалы из `charsPerSec` + джиттер.

**Дизайн-вилка (обязательная к закрытию).** Сейчас время набора «съедается» паузой до ввода (`turn.ts:155-161`); при порционном вводе его нужно исключить из `requiredBaseMs`, иначе мост платит дважды и становится МЕДЛЕННЕЕ человека — нарушение П-1 в другую сторону.

**Ограничения.** Ф-4 не меняется (сверка после полного ввода). Задокументировать в protocol-v3.md.

**Приёмка.** Тест на отсутствие двойного учёта времени; сверка Ф-4 в chunks; дефолт instant не меняет существующие тесты.

## У-4 — stopGeneration: обычный click вместо force:true

Приоритет: **низкий** · [ишью #4](https://github.com/dinered/codexpro/issues/4)

<!-- тело ишью: скопировать блок ниже -->

**Проблема.** Единственный мышиный жест в коде — `stop.click({ force: true, timeout: 2_000 })` (`src/driver/chatgpt.ts:87`). force обходит проверки actionability и может попасть в невидимый элемент; это и «неправильный» жест с точки зрения поведения.

**Предложение.** Обычный `click()` с ожиданием actionability; тайм-аут обработать штатно (клик может не состояться — генерация уже останавливается по другим признакам).

**Приёмка.** Контрактный тест: «Стоп» нажимается на видимой кнопке без force; сбой клика не фатален для закрытия хода.

## У-5 — README: правила запуска Chrome + раздел «Что видит платформа»

Приоритет: **низкий** · [ишью #5](https://github.com/dinered/codexpro/issues/5)

<!-- тело ишью: скопировать блок ниже -->

**Проблема.** Команда запуска Chrome в README верная (`--remote-debugging-port` + отдельный профиль), но не объяснена.

**Предложение.**
- запускать БЕЗ `--enable-automation` и подобных флагов → `navigator.webdriver = false`;
- профиль держать постоянным (`--user-data-dir=$HOME/.chatgpt-bridge-chrome`) → куки/история накапливаются, устройство «старое»;
- честный подраздел «Что видит платформа»: CDP-подключение включает домены отладки (Runtime.enable), теоретически детектируемые продвинутыми WAF. Наш ответ — не маскировка, а легитимность и готовность остановиться (П-6).

**Приёмка.** README содержит раздел; ссылка на него из сообщения об ошибке подключения (`main.ts:103`).

## У-6 — Метрики сопротивления: счётчики challenge / rateLimit / backoff

Приоритет: **низкий** · [ишью #6](https://github.com/dinered/codexpro/issues/6)

<!-- тело ишью: скопировать блок ниже -->

**Проблема.** `bridge-metrics.json` содержит ходы/отправки/серию ошибок/фатал (`src/metrics/metrics.ts`) — эксплуатационной картины сопротивления платформы нет.

**Предложение.** Добавить счётчики `challenge`, `rateLimit`, `backoff` (события + счётчики за окно). Бонус: материал для инцидент-репортов (упражнение курса К-5) и для различения «капча» vs «платформа режет запросы» (после У-2).

**Приёмка.** Метрики пишутся при каждом событии; отказ записи не останавливает мост (как сейчас); тест на состав файла.
