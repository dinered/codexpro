# Мост Paseo → web ChatGPT (протокол v3)

Мост превращает web ChatGPT в очередного провайдера Paseo: плагин-провайдер ставит ходы в
общий каталог `spool/`, мост вводит задачу в чат с человеческим темпом, дожидается ответа
и возвращает markdown. Граница «плагин / мост» — только протокол v3 (см. `docs/protocol-v3.md`):
любой исполнитель, реализующий ту же сторону протокола, заменяет мост без правок плагина (Ф-9).

Документация: `ARCHITECTURE.md` — модули и границы; `docs/protocol-v3.md` — протокол.

## Состав

| Каталог | Модуль | Назначение |
|---|---|---|
| `src/core/` | ядро | типы, таксономия ошибок, часы, ГСЧ (П-5), журнал (Ф-8) |
| `src/protocol/` | протокол v3 | spool: task/alive/cancel/claim/lease/state/result/journal, очередь (Ф-3) |
| `src/pace/` | темп | пауза человека, часовое окно 30/60, серия ошибок (§4 birdview, §10 ТЗ) |
| `src/driver/` | драйвер | интерфейс платформы + web ChatGPT (Playwright/CDP) + заглушка «человек» |
| `src/md/` | markdown | HTML ответа → markdown (Ф-5) |
| `src/metrics/` | метрики | файл состояния: счётчики, отправки, серия ошибок (birdview §1) |
| `src/bridge/` | движок | автомат хода, точка невозврата, детектор конца ответа, цикл моста |
| `plugin-client/` | референс-клиент | вторая сторона протокола: put/cancel/wait/ack (Ф-9, Д-7) |
| `selectors/` | профили | адрес и селекторы платформы — один файл, самопроверка на старте |
| `tests/` | тесты | unit, контрактный набор (Ф-9), модельный тест Н-1 |

## Запуск

Боевой режим (Chrome уже открыт с отладкой по CDP, профиль отдельный, порт только localhost):

```bash
google-chrome --remote-debugging-port=9222 --user-data-dir="$HOME/.chatgpt-bridge-chrome" https://chatgpt.com/
npm start -- /путь/к/spool          # мост подключается к вкладке сам
```

Демо без браузера (платформа — заглушка «человек»):

```bash
npm run demo -- /tmp/demo-spool     # терминал 1: мост
npm run plugin -- put "вопрос"      # терминал 2: клиент плагина ставит ход и ждёт ответ
npm run plugin -- wait <id> 600     # досмотреть ход из прошлого запуска (секунды)
npm run plugin -- list              # очередь
npm run plugin -- stop <id>         # «Стоп» (Ф-1)
```

Тайм-аут ожидания клиента ≠ конец хода: каталог хода не трогается (мост может быть
в паузе темпа, бэкоффе или ожидании окна). Каталог удаляется только после result.ack —
неподтверждённый ход нельзя сносить вместе с его журналом идемпотентности (Н-1).

Демо соблюдает нормативный темп (первая отправка ждёт ~20–24 с, П-2). Для быстрых
демо: `PACE_MIN_INTERVAL_MS=2000 npm run demo -- /tmp/demo-spool`.

## Журнал (Ф-8)

Формат строки: `время UTC ISO 8601 · КОД · trace=… · turn=… · текст`. Коды:

`BRIDGE_START` `BRIDGE_STOP` `BRIDGE_FATAL` — старт/остановка/фатал; `TURN_CLAIM`
`TURN_INTERCEPT` `TURN_PHASE` — захват, перехват, фазы хода; `TURN_SEND` `TURN_OK`
`TURN_ERROR` `TURN_CANCEL` `TURN_ACK` `TURN_ACK_TIMEOUT` — отправка, ответ, ошибки,
отмена, подтверждение; `PACE_PAUSE` `PACE_WARN` `PACE_STOP` `PACE_BACKOFF` `RATE_LIMIT` —
темп; `ALIVE_EXPIRED` — ход снят плагином; `QUEUE_SKIP` — битый элемент очереди;
`CHALLENGE` — капча/ограничение (П-6); `SELFCHECK_FAIL` — селекторы не на месте.

Эксплуатация читает причины без кода: `TURN_ERROR … RATE_LIMIT` — окно темпа,
`IDEMPOTENCY_REJECT` — повторная отправка запрещена, `SEND_STATE_UNKNOWN` — ход
перехвачен после точки невозврата, `BRIDGE_FATAL … CHALLENGE` — мост остановлен из-за
платформы. Метрики — `bridge-metrics.json` рядом со spool.

## Диагностика: зависание (Д-5)

1. **Ход висит в `generating`.** Н-2: любой ход закрывается за `BRIDGE_MAX_TURN_MS`
   (30 мин). Если ход «висит» дольше — мост мёртв; смотрите `BRIDGE_FATAL` в журнале
   и метрики. Брошенный ход перехватит следующий мост после аренды (35 с).
2. **Очередь не двигается, в журнале `PACE_BACKOFF`.** Серия ошибок платформы: мост
   молчит до получаса — это штатно (Н-5). Проверьте чат вручную: возможно, капча
   (`CHALLENGE` остановит мост сам).
3. **Ход «залип» без результата, плагина нет.** Если alive не пульсирует 70 с, мост
   закрывает ход `cancelled/ALIVE_EXPIRED`. Каталоги с `result.json` без `result.ack`
   читаются клиентом плагина (`npm run plugin -- list`, `wait <id>`) и убираются
   `dispose` — только после подтверждения (Н-1); битый `result.json` клиент и очередь
   помечают явно (`result.json повреждён (…)`) — это не «ход закрыт» и не «хода нет».
4. **Как снять зависший ход вручную:** остановите мост (Ctrl+C — мягко, повторный —
   сразу), удалите `claim.*`/`lease.*`/`state.*` каталога хода и `cancel`-маркер —
   ход снова претендуем; либо просто запустите мост: перехват произойдёт по правилам §2.
5. **`IDEMPOTENCY_REJECT` у неотправленного хода** — падение между журналом и кликом.
   Это осознанная цена запрета дубля (birdview §2); решение — за оператором: удалить
   ход или снять его плагином. Журнал ретроградно не переписывается.

## Оговорённые потери конвертации (Ф-5)

Картинки не переносятся; формулы остаются плоским текстом; блоки внутри ячеек таблиц
склеиваются в строку, вложенная таблица спрямляется в ячейке внешней; текст не
экранируется — буквальные `* _ #` в тексте станут разметкой. Остальное — с точностью до
абзацев, списков, таблиц, кода, цитат и ссылок.

## Сверка введённого текста (Ф-4, правило Д-7)

Эталон ввода — plain text: `task.text` вводится как есть. Сверка снимает платформенное
экранирование и схлопывает пробельные пролёты (переводы строк, табуляции, nbsp — к одному
пробелу); разметка и служебные символы сохраняются, поэтому «2 * 3» не превращается
в «23», а разные тексты не склеиваются. Правило зафиксировано в `docs/protocol-v3.md`.

## Известные ограничения

- Аренда по mtime предполагает общие часы и общий диск (одна машина, macOS приёмки);
  сон машины дольше 70 с снимает ход. Другая топология — другое хранилище аренды.
- Сетевой стрим (усиление Ф-6) выключен по умолчанию: включается флагом
  `network_probe` в профиле платформы после проверки эндпоинтов.
- Селекторы привязаны к вёрстке на момент поставки; правится только
  `selectors/chatgpt.yaml`, пересборка не нужна. Кнопки ищутся списком кандидатов
  (подписи RU и EN + `data-testid`) с проверкой видимости, поэтому язык интерфейса и
  косметические смены вёрстки мост не ломают. Самопроверка на старте проверяет
  поле ввода; структурные селекторы проверяются первым же ходом.
- Порт отладки Chrome — только localhost; профиль отдельный; учётные данные вне репозитория.
