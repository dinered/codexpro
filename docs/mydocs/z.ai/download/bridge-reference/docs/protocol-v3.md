# Протокол v3: плагин ↔ мост

Документ достаточен для независимой реализации обеих сторон без чтения кода (Д-7).
Стороны работают на одной машине и делят каталог `spool/`.

## 1. Каталог хода

Ход = один каталог `spool/<id>/`. `id` = время постановки UTC в формате
`YYYYMMDDTHHMMSSZ` + случайный суффикс из 6 символов алфавита `2-7a-z`
(без `0`/`1`). Порядок очереди — лексикографический по `id`; при равных
секундах — по полю `createdAt` из `task.json`.

| Файл | Кто пишет | Механика |
|---|---|---|
| `task.json` | плагин | атомарно: tmp + rename; `{v:3, id, createdAt, traceId, text}`; `v` всегда `3`; `id` обязан совпадать с именем каталога |
| `alive` | плагин | создаётся первым пульсом; mtime обновляется каждые 10 с, пока ход в работе |
| `cancel` | плагин | маркер отмены («Стоп» в Paseo); создаётся один раз |
| `claim.<N>` | мост | эксклюзивное создание (O_EXCL); `N` — эпоха: максимальная существующая + 1 |
| `lease.<N>` | мост | создаётся первым пульсом; mtime обновляется каждые 10 с, пока владелец жив; пульс — отдельным таймером, вне цепочки фаз хода (в том числе на паузах темпа) |
| `state.<N>` | мост | текущая фаза эпохи `N`; атомарно: tmp + rename + fsync |
| `result.json` | мост | создаётся ровно один раз (O_EXCL): `{status: ok\|error\|cancelled, markdown?, code?, message?, traceId}`; валидация: `status` — из словаря, `traceId` обязателен, для `ok` — непустой `markdown`, для `error`/`cancelled` — `code`. Битый файл — это «повреждённый результат» (клиент и очередь сообщают явно), а не «результ нет» |
| `result.ack` | плагин | атомарное переименование `result.json` после прочтения; каталог хода удаляется после ack |
| `journal.jsonl` | мост | построчный журнал отправок: `{"ts":…, "taskId":"…"}`; дозапись с fsync перед нажатием кнопки |

## 2. Жизненный цикл хода

Фазы (содержимое `state.<N>`):

```
claimed → preparing → typing → sending → sent → generating → harvesting → result → confirmed
```

- `claimed` — захват создан, пульс запущен.
- `preparing` — валидация задачи, привязка к чату, ожидание свободного чата, пауза темпа.
- `typing` — ввод текста и сверка с задачей «без разметки»; не совпало — стереть и
  повторить (не более 2 повторов).
- `sending` — **точка невозврата**, порядок строго такой: `state=sending` (атомарно) →
  запись `taskId` в `journal.jsonl` (fsync) → нажатие «Отправить».
- `sent` — кнопка нажата, отправка зафиксирована в темпе.
- `generating` — ожидание конца ответа по совокупности признаков платформы.
- `harvesting` — снятие текста ответа и конвертация в markdown.
- `result` — `result.json` записан.
- `confirmed` — плагин подтвердил: переименовал `result.json` в `result.ack` или удалил
  каталог хода (удалять можно только после ack). Мост распознаёт оба варианта и
  не блокирует очередь ожиданием уже закрытого хода.

## 3. Права и обязанности сторон

**Плагин обязан:**
1. Ставить ход: каталог + `task.json` атомарно, затем `alive`.
2. Пульсировать `alive` каждые 10 с, пока ждёт результат (в том числе пока ждёт
   повторно командой `wait`). Молчание плагина 70 с (2 × LEASE_MS = 2 × 35 000 мс)
   означает «ход снят»: мост закроет его `cancelled`.
3. Отменять ход маркером `cancel` («Стоп»); пульс при этом продолжается — плагин ждёт результат.
4. Читать `result.json`, переименовывать его в `result.ack` (атомарно). Гонку читателей
   решает сам rename: результат получает ровно один читатель, проигравший возвращает
   «результ нет». Удалять каталог хода ТОЛЬКО после ack; тайм-аут ожидания каталог
   не трогает — ход может ещё работать (пауза темпа, бэкофф).
5. Не создавать `claim.*`, `lease.*`, `state.*`, `result.json`, `journal.jsonl`.

**Мост обязан:**
1. Брать ходы в порядке очереди; битые элементы пропускать с предупреждением.
2. Захватывать ход через `claim.<N>` (O_EXCL). Владеть = существовать максимальной
   эпохой и пульсировать `lease.<N>`.
3. Перед записью каждой фазы и результата сверять эпоху: появился `claim.<N+1>` —
   владение утрачено, работа над ходом прекращается (для моста это фатально).
4. Ход, чья `lease` максимальной эпохи не обновлялась ≥ `LEASE_MS` (35 000 мс),
   считается брошенным; старые `lease.<N>` игнорируются.
5. Писать `result.json` ровно один раз — при любом исходе хода (ok / error / cancelled).
   Брошенных ходов без результата не бывает.

## 4. Перехват брошенного хода

Новый исполнитель (рестарт, второй мост):

1. Находит ход без `result.json` с захватами, чья `lease` максимальной эпохи протухла.
2. Если `alive` свежий — создаёт `claim.<N+1>` (O_EXCL): победитель продолжает,
   проигравший гонку отступает и перепроверяет состояние.
3. Читает `state.<максимальной эпохи>`:
   - фаза до `sending` (`claimed`/`preparing`/`typing`) — ход исполняется заново с
     тем же `task_id`; фаза `typing` означает, что в поле ввода может лежать черновик
     прошлой эпохи — его можно стереть (черновик «принадлежит» ходу);
   - фаза `sending` или позже — повторная отправка запрещена: ход закрывается
     ошибкой `SEND_STATE_UNKNOWN`.
4. Проверяет `journal.jsonl`: `taskId` уже записан — ход закрывается ошибкой
   `IDEMPOTENCY_REJECT` без работы с платформой (осознанная цена: падение между
   журналом и кликом неотличимо от отправки — дубль запрещён абсолютно, Н-1).
   Повреждённый журнал — ошибка `JOURNAL_CORRUPT` для этого хода; журнал ретроградно
   не переписывается, решение за оператором.
5. Если `alive` протух — плагин мёртв: ход закрывается `cancelled/ALIVE_EXPIRED`
   (до отправки поле ввода стирается; после — как отмена после отправки).

Если `lease` свежая, а мост «мёртв» (рестарт супервизором < 35 с) — исполнитель
ждёт до конца аренды, затем перехватывает по правилам выше.

## 5. Отмена и остановка

- Мост проверяет `cancel` между фазами и каждые 500 мс в ожиданиях.
- До отправки: стереть введённое, `result.json` со статусом `cancelled` (код `CANCEL`).
- После отправки: остановить генерацию средствами платформы, дождаться холостого
  состояния ≤ 30 с (дольше — фатальная остановка моста), результат `cancelled`
  (код `CANCEL`), ответ не отдаётся.
- `alive` протух во время работы — то же, что отмена (код `ALIVE_EXPIRED`).
- Первый SIGINT/SIGTERM моста: неотправленный ход — `cancelled` (код `SIGNAL`);
  уже отправленный — прерывается и закрывается **ошибкой** `STOPPED` (Н-6).
  Второй сигнал — немедленный выход; брошенный ход закроет следующий мост по §4.

## 6. Коды ошибок результата

| Код | Смысл |
|---|---|
| `EMPTY_TASK` | пустая задача (ошибка хода, не остановка моста) |
| `TEXT_MISMATCH` | введённый текст не совпал с задачей после повторов |
| `CHAT_BUSY` | чат занят чужим ходом/черновиком дольше лимита (120 с) |
| `PLATFORM_ERROR` | отказ платформы (участвует в серии ошибок Н-5) |
| `EMPTY_ANSWER` | платформа закончила ход пустым «готовым» ответом |
| `TURN_TIMEOUT` | ход дольше `BRIDGE_MAX_TURN_MS` (1800 с) |
| `RATE_LIMIT` | часовой предел отправок (60/ч) — очередь ждёт окна, в серию ошибок не входит |
| `IDEMPOTENCY_REJECT` | `task_id` уже в журнале отправок — повторная отправка запрещена |
| `SEND_STATE_UNKNOWN` | владение утрачено на `sending` или позже — состояние отправки неизвестно |
| `JOURNAL_CORRUPT` | журнал повреждён; решение за оператором |
| `STOPPED` | мост остановлен оператором после отправки (Н-6) |
| `CANCEL` / `SIGNAL` / `ALIVE_EXPIRED` | отмена плагином / мягкая остановка до отправки / плагин не пульсирует |

Фатальные состояния (мост останавливается; ход закрывается ошибкой с кодом причины,
если владение ещё есть): утрата владения, уход вкладки с домена, нет поля ввода 10 с,
генерация не остановлена за 30 с, капча/принудительный выход/ограничение аккаунта
(`CHALLENGE`, П-6), spool недоступен, отказ записи результата (диск полон).

## 7. Минимальный клиент (пример стороны плагина)

```
put(text):
  id = <UTC-время>-<случайный суффикс>
  mkdir spool/<id>; write_atomic(spool/<id>/task.json, {v:3, id, createdAt, traceId, text})
  каждые 10 с: pulse(spool/<id>/alive)          # пока ход в работе
stop(id):   create(spool/<id>/cancel)
wait(id):   когда появился spool/<id>/result.json:
              если rename(spool/<id>/result.json, spool/<id>/result.ack) удался:
                  прочитать и отдать ответ          # результат — этому читателю
              иначе: результата нет (его забрал другой читатель)
            битый result.json — явная ошибка, не тихое ожидание
            тайм-аут ожидания: каталог НЕ трогать, пульс не бросать
dispose(id): только если result.ack существует: rm -r spool/<id>
```

Сверка введённого текста у моста (Ф-4): эталон ввода — plain text (`task.text`);
сравниваются стороны после снятия экранирования (`\*` → `*`) и схлопывания
пробельных пролётов (переводы строк/табуляции/nbsp — к одному пробелу).

Контрактный набор тестов прогоняется по мосту и по любой второй реализации протокола —
замена исполнителя не требует правок плагина (Ф-9).
