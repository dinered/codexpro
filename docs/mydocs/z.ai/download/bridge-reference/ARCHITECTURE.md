# Архитектура: модульность и универсальность

Документ отвечает на два вопроса: из чего состоит мост и почему его можно расширять,
не переписывая. Базис — утверждённый birdview v2.1 (BV-4): состав модулей из §1 birdview
воспроизведён один в один, каждая секция кода ссылается на пункт birdview или ТЗ.

## Карта модулей

```
                    ┌────────────────────────────────────────────────┐
                    │                 src/core/ (ядро)               │
                    │  types · errors · clock · random · log         │
                    └───────────────▲────────────────▲───────────────┘
                                    │                │
   плагин ─── протокол v3 ───► src/protocol/ ◄──────┤
   (plugin-client/)           spool, эпохи, журнал   │
                                    ▲                │
                                    │                │
                             src/bridge/ ───────────┤
                        turn (автомат хода,         │
                        точка невозврата),          │
                        completion, loop            │
                            │            │          │
                    src/pace/      src/md/ · src/metrics/
                    (темп §4)      (Ф-5)     (файл состояния)
                            │
                    src/driver/ ◄── ЕДИНСТВЕННАЯ привязка к платформе
                    ChatDriver ◄─── chatgpt (Playwright/CDP) · human (Ф-9)
                                    selectors/<платформа>.yaml + cdp-stream
```

Правила зависимостей (проверяются на code review, не инструментом):

1. **Ядро не знает ничего.** `core/` — типы, ошибки, часы, ГСЧ, журнал. Ни диска, ни сети.
2. **Протокол не знает про ChatGPT.** `protocol/` — только файловые операции. Его можно
   вынести в отдельный пакет и переиспользовать в плагине (референс-клиент уже так делает).
3. **Движок не знает про вёрстку.** `bridge/` общается с платформой только через
   интерфейс `ChatDriver`. Точка невозврата и детектор конца ответа — у моста, не у драйвера.
4. **Драйвер не знает про протокол.** `driver/` получает текст, нажимает «Отправить»,
   отдаёт снимки страницы. Никаких claim/lease внутри.
5. **Время — только через Clock, случай — только через Random.** Поэтому весь этот код
   тестируется на подставных часах (birdview §5), а ГСЧ в бою — из crypto (П-5).

Соответствие birdview §1: `protocol` → `src/protocol/`, `pace` → `src/pace/`,
`driver` → `src/driver/` + `selectors/`, `md` → `src/md/`, `log` → `src/core/log.ts`,
`metrics` → `src/metrics/`, «плагин» → `plugin-client/`.

## Модульность: где что ищется

| Обязательство birdview | Где в коде |
|---|---|
| Точка невозврата: state=sending → journal → клик (§2) | `bridge/turn.ts`, фаза `sending` |
| Перехват по аренде, эпохи, «победитель продолжает, проигравший отступает» (§2) | `protocol/claim.ts` + решение `bridge/loop.ts#decide` |
| Пульс отдельным таймером, вне фаз (Н-1) | `protocol/claim.ts`, класс `LeasePulser` |
| Результат ровно один раз (Н-1) | `protocol/result.ts` (O_EXCL) |
| Отказная матрица (§3) | `core/types.ts` (коды) + `bridge/turn.ts`/`bridge/loop.ts` (реакции) |
| Формула темпа, односторонний джиттер (§4) | `pace/pace.ts` (чистые функции + `Pacer`) |
| Окно стабильности 3–5 с, первичный признак (Ф-6) | `bridge/completion.ts` |
| Селекторы одним файлом + selftest (§1, §6) | `selectors/chatgpt.yaml` + `driver/selectors.ts`, `driver/chatgpt.ts#selftest` |

## Универсальность: добавление платформы

Ядро развязано с платформой интерфейсом `ChatDriver` (`driver/types.ts`): привязка к чату,
поле ввода, ввод/сверка/очистка, клик, снимок ответа, «Стоп», домен, капча, самопроверка.
Новая платформа подключается без правок `core/`, `protocol/`, `pace/`, `bridge/`, `md/`:

1. **Профиль** — `selectors/<платформа>.yaml`: адрес, домен, селекторы (обязательные:
   поле ввода, ход/пара, ответ, кнопка «Стоп»; необязательные уточняют Ф-6).
2. **Драйвер** — класс, реализующий `ChatDriver` (для web-платформы — поверх Playwright;
   для нативного приложения — тот же интерфейс поверх доступного канала управления,
   например accessibility/скриптового; движок не отличит).
3. **Реестр** — расширить выбор драйвера в `src/main.ts` (`BRIDGE_DRIVER`).
4. **Тесты** — контрактный набор (`tests/contract/`) прогоняется против любого драйвера:
   это и есть проверка Ф-9 «замена исполнителя без правок плагина».

Что при этом **не меняется**: протокол v3, автомат хода и точка невозврата, темп,
детектор конца ответа (снимки одинаковы для всех), конвертер markdown, журнал, метрики,
весь комплект unit/contract/chaos — сценарии переиспользуются с новым драйвером.

Где расширение НЕЛЬЗЯ делать: драйвер не должен знать про фазы/аренду (сломается Н-1),
движок не должен содержать селекторов (сломается универсальность), темп не должен
зависеть от платформы (П-5 про ритм, не про вёрстку).

## Инварианты и как они держатся

- **Н-1 (ответ ровно один раз):** O_EXCL на `result.json` + эпохи на каждой записи (проверка
  до и после записи фазы) + журнал до клика + запрет повторной отправки после точки
  невозврата. На стороне плагина: гонку читателей решает атомарный rename (`result.ack` —
  результат получает ровно один читатель), удаление каталога разрешено только после ack,
  тайм-аут ожидания каталог не трогает. Битый `result.json` — явная ошибка (`corrupt`),
  а не «результ нет». Проверяется модельным тестом `tests/chaos/h1.test.ts` (два моста,
  падения на каждой фазе, включая запись фаз) и контрактами 13–16.
- **Н-2 (конечность ожиданий):** у каждого ожидания свой лимит (см. переменные
  `BRIDGE_*_WAIT_MS`) плюс общий срок хода.
- **Владение освобождается всегда (Ф-2):** пульс остановится в `finally` исполняющего
  кода при любом исходе, включая «смерть» в модельных тестах.
- **Отмена на любой фазе (Ф-1):** единый guard между фазами и каждые 500 мс в ожиданиях;
  до отправки — стереть поле, после — «Стоп» и холостое ≤ 30 с.
