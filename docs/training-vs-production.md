# Учебная реализация и боевая: в чём разница

Документ для разбора с учениками. Здесь собрано всё, чем учебный codexpro
(плагин Paseo, мост в ChatGPT, песочницы) отличается от того, как такую же
задачу решали бы в боевой системе. Для каждого отличия: как сделано сейчас,
как было бы в бою, почему в учебном сделано так и чем это грозит.

«Боевое» здесь — не план проекта. Проект учебный и боевым не станет
(`AGENTS.md`). Это образец для сравнения: что пришлось бы поменять, если бы ту
же задачу решали всерьёз.

## Как читать и как искать в коде

Каждое отличие помечено в коде меткой `#учебно-не-боевое-NN`, где `NN` — номер
раздела ниже. Метка стоит ровно там, где живёт отличие:

```sh
git grep -n "#учебно-не-боевое"       # все места
git grep -n "#учебно-не-боевое-07"    # одно отличие
```

У каждого раздела есть строка **Где:** — файлы, в которых стоит его метка.
Номера, метки и строки «Где» сверяет проверка, без сети и зависимостей:

```sh
node --test tools/docs-check/markers.test.mjs
```

Проверка падает, если у раздела нет метки в коде, метка ссылается на
несуществующий номер, номер повторяется или файлы в «Где» не совпадают с
файлами, где стоит метка. Новое отличие добавляется так: раздел со следующим
номером, метка в коде, строка в сводной таблице.

Метки не путать с двумя другими (`AGENTS.md`):

| Метка | Что отмечает |
| --- | --- |
| `#внимание-учебно-аналитический-предохранитель` | ограничение автоматизации ChatGPT: лимит, пауза, запрет, остановка |
| `#модельный-учебно-аналитический-контроль` | место, где Claude сверяет, что работа не вышла за учебные рамки |
| `#учебно-не-боевое-NN` | решение, которое в боевой системе было бы другим |

Предохранитель часто и есть учебное отличие: в бою его заменило бы устройство
системы (например, лимит по квоте API вместо счётчика сообщений). Тогда у места
две метки.

## Главное в одном абзаце

Учебный мост вводит текст в веб-интерфейс ChatGPT через браузер оператора и
читает ответ со страницы. Условия OpenAI это запрещают
(`tools/chatgpt-bridge/README.md`), поэтому **мост нельзя «довести до боевого»:
в бою его заменяют целиком** — официальным API модели с ключом организации.
Отличия 01–06 и почти все предохранители моста есть только потому, что
транспорт — чужой интерфейс. Плагин Paseo и протокол обмена файлами (07–13) переносятся,
но в бою вместо папки с файлами была бы очередь сообщений, а состояние хода
хранилось бы надёжно. Песочницы, секреты и эксплуатация (14–24) — типичные
упрощения стенда на одном ноутбуке.

## Транспорт к модели

### 01. Канал к модели — веб-интерфейс ChatGPT

**Где:** `tools/chatgpt-bridge/bridge.ts`, `tools/chatgpt-bridge/main.ts`

- **Учебно.** Мост подключается к Chrome оператора по CDP (протокол отладки
  Chrome), вводит текст в поле чата клавиатурой и ждёт ответ на странице.
- **Боевое.** Вызов официального API модели (OpenAI API или другой
  провайдер) из самого провайдера Paseo: ключ организации, договор, условия
  обработки данных. Мост, браузер, Chrome, CDP и прокси не нужны вовсе.
- **Почему так.** Цель задачи — разобрать, как веб-ChatGPT из подписки
  встраивается в Paseo (`docs/integration-options.md`, вариант 4б); у API
  другие модели и другая оплата.
- **Чем грозит.** Нарушение условий OpenAI и риск для аккаунта; хрупкость при
  любой смене интерфейса. Поэтому прогоны редкие, ручные, под предохранителями.
  Укреплять мост дальше бессмысленно: в бою его не чинят, а заменяют.

### 02. Разметка страницы как контракт

**Где:** `tools/chatgpt-bridge/bridge.ts`, `tests/e2e/fake-chatgpt.html`

- **Учебно.** Контракт с ChatGPT — селекторы `SEL`, снятые с живой страницы
  2026-10-06, и подписи кнопок на русском («Остановить», «Сгенерировать ответ
  заново»). Имитация в тестах повторяет ту же разметку.
- **Боевое.** Версионированный API с документированной схемой ответа и
  статусом завершения. Смена версии — по плану, со сроком поддержки старой.
- **Почему так.** У веб-интерфейса нет публичного контракта; опереться можно
  только на то, что видно на странице.
- **Чем грозит.** ChatGPT меняет разметку без предупреждения; сменился язык
  интерфейса — мост не находит кнопок. Тесты на имитации этого не поймают:
  имитация меняется только руками.

### 03. Ответ собирается из разметки страницы

**Где:** `tools/chatgpt-bridge/bridge.ts`

- **Учебно.** `readTurn` обходит DOM ответа и восстанавливает markdown:
  списки, таблицы, код, ссылки. Картинки, формулы и блоки внутри ячеек таблиц
  упрощаются.
- **Боевое.** API возвращает текст ответа таким, каким его выдала модель, —
  восстанавливать нечего.
- **Почему так.** Со страницы доступна только отрисованная разметка.
- **Чем грозит.** Потери при обратном преобразовании: ответ в Paseo может
  отличаться от того, что сгенерировала модель.

### 04. Сбои распознаются по косвенным признакам

**Где:** `tools/chatgpt-bridge/bridge.ts`

- **Учебно.** Лимит, капчу и ошибку мост различает только по тому, чего на
  странице нет: сообщение не принято за 2 минуты, ответ не начался, не
  закончился за 10 минут, пришёл пустым. На любой такой сбой мост
  останавливается целиком и ждёт человека. Ошибку после части ответа он не
  отличает от конца ответа (README моста, «Известные ограничения»).
- **Боевое.** Явные коды ответа API (429 — лимит, 5xx — сбой сервиса),
  заголовки с остатком квоты и временем ожидания. Временные сбои — повтор с
  растущей паузой; серия сбоев — «предохранитель цепи» (circuit breaker)
  временно перестаёт слать запросы; алерт дежурному.
- **Почему так.** Повторять в чужом интерфейсе нельзя: это и есть обход
  ограничений, который запрещают условия OpenAI. Остановиться и позвать
  человека — единственное честное действие.
- **Чем грозит.** Обрезанный ответ может уйти в Paseo как полный; каждый сбой
  требует ручного перезапуска.

### 05. Лимиты и паузы — константы на запуск

**Где:** `tools/chatgpt-bridge/bridge.ts`

- **Учебно.** Не больше 20 сообщений за запуск (явно — до 500) и не чаще
  одного в 20 секунд. Считает каждый мост сам; два моста на разных каталогах
  считают раздельно. Длина сообщения и ответа не учитывается.
- **Боевое.** Ограничение по квоте поставщика (запросы и токены в минуту) и по
  бюджету в деньгах, общее для всех экземпляров: отдельный лимитёр (например,
  «ведро токенов» в Redis) или шлюз API. Квоты — на команду или клиента.
- **Почему так.** Цель лимита здесь — не нагрузка, а учебные рамки: прогон
  должен оставаться коротким и редким.
- **Чем грозит.** Лимит можно обойти перезапуском с новым `--limit` — защита
  держится на дисциплине и на чек-листе (21).

### 06. «Не больше одного раза» — с ручной сверкой

**Где:** `tools/chatgpt-bridge/bridge.ts`

- **Учебно.** Мост помнит отправленное в памяти (`sentIds`) и никогда не
  повторяет Enter. Если мост упал посреди хода, сообщение могло уйти, а могло
  и нет: мост отказывается отправлять такую задачу, а человек открывает чат и
  проверяет глазами.
- **Боевое.** Повтор запроса к API безопасен: он не появляется вторым
  сообщением в чужом чате. Дубликаты отсекает ключ задачи в очереди
  (идемпотентность на стороне получателя), результат пишется в хранилище один
  раз.
- **Почему так.** Чат ChatGPT — внешнее состояние, которое нельзя ни
  откатить, ни спросить «было ли это сообщение».
- **Чем грозит.** После падения ход нужно разбирать вручную.

## Плагин Paseo и протокол обмена

### 07. Файловый «почтовый ящик» вместо очереди

**Где:** `tools/paseo-plugin/server/protocol.ts`

- **Учебно.** Плагин и мост обмениваются файлами в `.ai-bridge/paseo/<сессия>/`:
  `task-`, `claim-`, `reply-`, `error-<id>`. Протокол v2 — один модуль на
  обе стороны.
- **Боевое.** Брокер сообщений (RabbitMQ, NATS, SQS и т. п.) с
  подтверждением обработки, повторной выдачей неподтверждённого и очередью
  «мёртвых» сообщений (DLQ). Или вовсе без посредника: провайдер Paseo сам
  вызывает API (01), и очередь не нужна.
- **Почему так.** Файлы видны глазами, их можно написать руками
  (`echo "Ответ" > reply-<id>.md`), они не требуют инфраструктуры и одинаково
  работают на Маке и в контейнере. Это лучший формат для разбора протокола.
- **Чем грозит.** Нет гарантий доставки, порядка и ограничения по размеру;
  работает только на одной машине с общей папкой.

### 08. Аренда по времени файла

**Где:** `tools/paseo-plugin/server/protocol.ts`

- **Учебно.** «Жив ли владелец» — по mtime файла: пульс раз в 5 с, срок 30 с.
  Захват — создание файла с `O_EXCL`. Если двое одновременно перехватывают
  брошенный захват, один может снять свежий захват другого; это ловит сверка
  токена на каждом пульсе.
- **Боевое.** Аренда в брокере (visibility timeout) или в БД с атомарным
  сравнением и заменой; токен ограждения (fencing token) — растущий номер,
  по которому хранилище отвергает запись от владельца с просроченной арендой.
- **Почему так.** Файловая система даёт ровно два атомарных действия: создать
  с `O_EXCL` и переименовать. Из них этого достаточно для учебного протокола.
- **Чем грозит.** Зависимость от часов и точности mtime на томах Docker;
  узкое окно гонки при перехвате.

### 09. Долговечность записи — «по возможности»

**Где:** `tools/paseo-plugin/server/protocol.ts`

- **Учебно.** Запись атомарна (временный файл, `fsync`, `rename`), но `fsync`
  папки — по возможности: часть ФС (virtiofs, тома Docker) его не умеет, и
  ошибка молча пропускается.
- **Боевое.** Хранилище с заявленными гарантиями: брокер с подтверждённой
  записью на диск или реплики, БД с журналом.
- **Почему так.** Стенд — ноутбук; потеря файла при сбое питания не страшна:
  ход просто завершится ошибкой.
- **Чем грозит.** После аварии файл ответа может пропасть, хотя мост уже
  записал его в журнал как отданный.

### 10. Опрос вместо уведомлений

**Где:** `tools/paseo-plugin/server/provider.ts`, `tools/chatgpt-bridge/bridge.ts`

- **Учебно.** Плагин опрашивает папку, мост — папку и страницу, раз в
  секунду. Ответ виден с задержкой до двух периодов опроса.
- **Боевое.** События: подписка на очередь, поток ответа модели (streaming),
  на странице — `MutationObserver`. Задержка — доли секунды, холостой нагрузки
  нет.
- **Почему так.** `fs.watch` ненадёжен на томах Docker; опрос прост и
  предсказуем, его легко проверить в тестах.
- **Чем грозит.** Лишняя задержка и холостые чтения диска; при многих сессиях
  опрос не масштабируется.

### 11. Состояние хода только в памяти

**Где:** `tools/paseo-plugin/server/provider.ts`

- **Учебно.** Активный ход живёт в памяти процесса плагина. Перезапуск демона
  Paseo теряет ход: файл задачи перестаёт пульсировать, исполнители его не
  берут.
- **Боевое.** Состояние ходов — в хранилище; провайдер поддерживает
  `session.persistence` Paseo и после перезапуска продолжает ожидание.
- **Почему так.** Ход короткий, человек рядом и может отправить сообщение
  заново; восстановление удвоило бы плагин.
- **Чем грозит.** Потерянный ход, если ответ ChatGPT пришёл во время
  перезапуска.

### 12. Один ход за раз, только текст

**Где:** `tools/paseo-plugin/server/provider.ts`

- **Учебно.** В сессии одна задача за раз; сообщение во время хода
  отклоняется (steer не поддержан); вложения не передаются.
- **Боевое.** Очередь сообщений сессии или steer, вложения (файлы, картинки),
  несколько сессий параллельно с общим лимитом (05).
- **Почему так.** Мост всё равно работает с одним чатом последовательно;
  параллельность ничего бы не дала, а протокол усложнила бы.
- **Чем грозит.** Только неудобство: пользователь ждёт ответа или жмёт «Стоп».

### 13. Граница доверия — общая рабочая папка

**Где:** `tools/paseo-plugin/server/protocol.ts`

- **Учебно.** В режиме codexpro ChatGPT сам пишет в рабочую папку — ту же, где
  лежат файлы протокола. Защита — гигиена файлов: чтение без перехода по
  ссылкам (`O_NOFOLLOW`), атомарная замена, отказ от FIFO и не-файлов. Кто
  написал `reply-<id>.md` — мост, человек или ChatGPT, — не проверяется.
- **Боевое.** Канал управления отделён от данных: протокол — в каталоге или
  очереди, куда модель доступа не имеет; разные учётные записи ОС; сообщения
  подписаны (HMAC) и проверяются получателем.
- **Почему так.** Учебная цель — увидеть, какие атаки возможны через общую
  папку и как их гасить на уровне файлов.
- **Чем грозит.** ChatGPT может подложить ответ на текущий ход в обход моста.
  Считать ли переписку каналом управления агентами — решение оператора
  (ai/codexpro#2, README моста).

## Песочницы, сеть и секреты

### 14. CDP без пароля и проверка Chrome по `ps`

**Где:** `tools/chatgpt-bridge/cli.ts`, `tools/codexpro-sandbox/README.md`

- **Учебно.** CDP Chrome открыт на `127.0.0.1:9222` без пароля, и до него
  достают контейнеры OrbStack. «Тот ли это Chrome» мост решает по командной
  строке процесса из `lsof` и `ps`, а «кто ещё рядом» — по списку контейнеров
  `docker` и машин `orb`. Неоднозначное трактуется в сторону отказа.
- **Боевое.** Браузера нет (01). Если он всё же нужен (например, для
  тестов интерфейса) — отдельная машина или ВМ без других жильцов, CDP через
  аутентифицированный канал, отпечаток процесса не угадывается, а задаётся
  оркестратором.
- **Почему так.** Стенд — ноутбук оператора; отдельная машина ради редких
  прогонов не окупается.
- **Чем грозит.** Любой процесс в любом контейнере может управлять этим Chrome
  со входом в ChatGPT; разбор `ps` — эвристика, а не доказательство.

### 15. Сеть проверяется один раз при запуске

**Где:** `tools/chatgpt-bridge/main.ts`

- **Учебно.** Мост спрашивает mihomo, стоит ли группа `FOREIGN` на
  `FOREIGN_STRICT`, и проверяет флаги прокси у Chrome — один раз, до
  подключения. Переключить группу после старта мост не помешает и не заметит.
- **Боевое.** Маршрут закреплён инфраструктурой: исходящий трафик сервиса
  выпускает только сетевая политика или шлюз, и другого пути нет. Приложение
  не проверяет сеть — оно не может её обойти.
- **Почему так.** Прокси — настройка рабочего Мака оператора, а не
  инфраструктура проекта (`AGENTS.md`).
- **Чем грозит.** Разрыв между проверкой и использованием (TOCTOU): смена
  выхода во время прогона пройдёт мимо моста.

### 16. Личный аккаунт оператора

**Где:** `tools/chatgpt-bridge/main.ts`, `tools/chatgpt-bridge/README.md`

- **Учебно.** Мост работает от имени основного аккаунта ChatGPT оператора — с
  его памятью, историей и подключёнными коннекторами (в том числе боевым
  `CodexPro`). Защита — чек-лист: выключить коннекторы и память, ничего
  чувствительного в сообщениях.
- **Боевое.** Сервисная учётная запись организации с минимальными правами,
  ключ API в хранилище секретов, отдельный ключ на сервис, ротация, журнал
  использования у поставщика.
- **Почему так.** Задача — именно веб-ChatGPT из подписки оператора (01).
- **Чем грозит.** В ответ может попасть личное из памяти ChatGPT; ошибка
  оператора открывает модели боевой коннектор.

### 17. Секреты в файлах и URL

**Где:** `tools/codexpro-sandbox/README.md`, `tools/paseo-sandbox/README.md`, `tests/e2e/paseo.spec.ts`

- **Учебно.** Токен codexpro — в файле на томе и в URL туннеля
  (`?codexpro_token=`), туннель — временный `trycloudflare.com`. Пароль Paseo —
  в `paseo.env` (0600), тест читает его из того же файла. Защита — права на
  файлы и правило «не печатать на экран, только в буфер обмена».
- **Боевое.** Хранилище секретов (Vault, менеджер секретов облака, CI-переменные
  с маскированием); токен — в заголовке `Authorization`, не в URL; постоянный
  именованный туннель или Zero Trust с входом по SSO, mTLS; плановая ротация и
  отзыв.
- **Почему так.** Всё живёт на одном ноутбуке, срок жизни секрета — прогон.
- **Чем грозит.** Токен в URL оседает в истории браузера и логах; кто видит
  логи контейнера, видит и токен.

### 18. Изоляция песочниц только файловая

**Где:** `tools/codexpro-sandbox/Dockerfile`, `tools/codexpro-sandbox/README.md`

- **Учебно.** Контейнер `codexpro-sandbox` видит только `/workspace`, но по
  сети достаёт до всех сервисов Мака на `127.0.0.1`. Образ — `node:22-slim`
  по тегу, пакеты `apt` без версий.
- **Боевое.** Сетевая политика «запрещено всё, кроме нужного», корневая ФС
  только для чтения, сброшенные capabilities, отдельная сеть. Образ закреплён
  по дайджесту, версии пакетов зафиксированы, образ сканируется на уязвимости
  и подписывается.
- **Почему так.** OrbStack на Маке не даёт простой сетевой изоляции от хоста;
  риск закрыт правилом «не запускать вместе с Chrome с CDP», которое проверяет
  мост.
- **Чем грозит.** ChatGPT с `bash safe` может выполнить в контейнере любой код
  и дотянуться до сервисов Мака; пересборка образа даёт другие версии пакетов.

## Эксплуатация и процесс

### 19. Запуск вручную, пути в коде

**Где:** `tools/chatgpt-bridge/main.ts`

- **Учебно.** Мост запускает человек из терминала. Пути
  (`~/work/ai/codexpro/2`, сокет mihomo), порты (9222, 17891) и контекст
  `docker` записаны в коде.
- **Боевое.** Сервис под супервизором (systemd, Kubernetes) с проверками
  здоровья; конфигурация — из переменных окружения или файла, проверяется
  схемой при старте; одинаковый артефакт на всех окружениях.
- **Почему так.** «Только вручную» — сам по себе предохранитель (ai/codexpro#2,
  п. 6): у моста нарочно нет демона и расписания. Стенд один, настраивать
  нечего.
- **Чем грозит.** Перенос на другую машину требует правки кода.

### 20. Журнал — текстовый файл

**Где:** `tools/chatgpt-bridge/main.ts`

- **Учебно.** Строки «время UTC + событие» дописываются в `bridge-runs.log`;
  прогон сверяют глазами по чек-листу. Текстов задач и ответов в журнале нет.
- **Боевое.** Структурные логи (JSON) с идентификатором хода во всех строках,
  сбор в централизованное хранилище; метрики (отправлено, время ответа,
  ошибки), трассировка от сообщения в Paseo до ответа модели; алерты по
  порогам; журнал аудита, который нельзя исправить задним числом.
- **Почему так.** Прогонов единицы, читатель — оператор и Claude.
- **Чем грозит.** Журнал можно отредактировать; по нему не построить
  статистику и не получить сигнал о сбое без человека.

### 21. Контроль рамок — чек-лист и нота

**Где:** `tools/chatgpt-bridge/README.md`

- **Учебно.** Что прогон не вышел за учебные рамки, проверяют оператор и Claude
  по чек-листу «Живой прогон»; разрешение и итог — ноты в Issue.
- **Боевое.** Правила в коде самой системы (policy as code): квоты и запреты
  применяются автоматически, согласование — шаг в системе с записью, кто и
  когда разрешил; периодический аудит.
- **Почему так.** Этот контроль — учебный материал сам по себе: ученики
  разбирают, что машина проверить может, а что остаётся человеку.
- **Чем грозит.** Пропущенный пункт чек-листа ничего не остановит.

### 22. Тесты на имитации, без CI

**Где:** `tests/e2e/playwright.config.ts`, `tools/chatgpt-bridge/bridge.ts`

- **Учебно.** Мост тестируется против имитации `fake-chatgpt.html`, которая
  повторяет разметку на дату замера (02). Тест `paseo` требует контейнер на
  Маке оператора. В CI тестов нет: задание `smoke` печатает `smoke ok`, тесты
  гоняют руками. Ядро моста принимает параметры только для тестов —
  `pauseMs` меньше 20 с и `acceptQueued`.
- **Боевое.** Все тесты — в CI на каждый MR, обязательные для слияния;
  контрактные тесты против песочницы поставщика API; нужное для тестов
  подставляется зависимостями (часы, источник задач), а не флагами в боевом
  коде.
- **Почему так.** Живой ChatGPT в CI запускать нельзя (01), а раннер проекта —
  общий shell-раннер; `.gitlab-ci.yml` меняется только по просьбе оператора.
- **Чем грозит.** Регрессию заметят только при ручном прогоне; тестовые
  параметры ядра можно передать и не в тесте — их держит только соглашение.

### 23. Сборка и поставка

**Где:** `tools/paseo-plugin/README.md`, `tools/paseo-sandbox/README.md`

- **Учебно.** TypeScript исполняется напрямую (`node main.ts`, плагин — как
  исходники), без сборки. Плагин копируется в песочницу `rsync`, версия
  `0.0.0`. Paseo — beta `0.11.0-beta.5`; версии dev-зависимостей с `^`, точные
  версии держит только `package-lock.json`.
- **Боевое.** Сборка в CI, версионированный подписанный артефакт, список
  компонентов (SBOM), выкладка тем же артефактом на все окружения, откат на
  прошлую версию; стабильные релизы зависимостей и автоматические обновления
  с проверкой (Renovate, Dependabot).
- **Почему так.** Учебный цикл «поправил — перезагрузил плагин» должен быть
  коротким, а Paseo с провайдерами-плагинами пока есть только в beta.
- **Чем грозит.** Что именно работает в песочнице, знает только тот, кто
  копировал; beta Paseo может сломать API плагинов.

### 24. Правки в `main` мимо MR

**Где:** `docs/github-sync.md`

- **Учебно.** При работе на GitHub правки идут коммитами прямо в `main` и
  приходят в GitLab заданием синхронизации — мимо MR, merge train и ревью
  (решение оператора, ai/codexpro#4).
- **Боевое.** Один источник правды; `main` защищён, изменения — только через
  MR с ревью и зелёным CI; зеркало — только для чтения.
- **Почему так.** Оператор работает с учениками по очереди в двух системах;
  ревью здесь — разбор с учениками, а не барьер.
- **Чем грозит.** Непроверенная правка сразу в `main` обеих сторон.

## Что уже сделано по-боевому

Не всё в учебном коде упрощено. Эти решения переносятся в боевую систему как
есть, и на них стоит смотреть как на образец:

- **Атомарная запись** (`writeAtomic`): временный файл, `fsync`, `rename` —
  читатель видит файл целиком или не видит вовсе.
- **Гигиена файлов**: чтение без перехода по ссылкам, отказ от FIFO, создание
  с `O_EXCL`. Те же приёмы нужны любому сервису, который читает файлы из
  чужой папки.
- **Отказ по умолчанию**: при неясности (docker не ответил, `ps`
  неоднозначен, очередь не пуста) мост не запускается.
- **Один модуль протокола на обе стороны**: формат не может разойтись между
  плагином и мостом.
- **Чистые функции решений** (`cli.ts`): проверки окружения тестируются без
  docker, Chrome и терминала.
- **Тесты на граничные случаи**: гонки, ссылки, падения, сон Мака, повторный
  сигнал — всё воспроизводится на имитации.
- **Секреты не печатаются**: только в файл с правами 0600 или в буфер обмена.

## Если бы это делали всерьёз: порядок перехода

1. Заменить мост вызовом API модели прямо в провайдере Paseo (01). Вместе с
   мостом уходят 02–06, 14–16 и большая часть 19–20.
2. Если исполнитель остаётся отдельным процессом — очередь сообщений вместо
   папки (07–10), состояние ходов в хранилище (11).
3. Секреты — в хранилище, токены — в заголовках (17), изоляция и
   закреплённые образы (18).
4. CI с тестами на каждый MR, сборка и артефакты (22, 23), `main` только
   через MR (24).
5. Наблюдаемость и правила в коде системы (20, 21).
