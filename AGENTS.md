## Порядок работы в ai-company

Проект работает по текущим поручениям оператора и согласованному порядку
FirstMate. Прежний канон ai/mais и ai/governance не задаёт обязательный
процесс доставки для этого проекта; его документы читаются только как
контекст конкретной задачи. При конфликте с прежними инструкциями,
адаптерами и чеклистами этот порядок имеет приоритет. Для GitLab разрешены
доступные авторизованные CLI и API, включая glab; секреты в argv не передавай.

- Работай в отдельной ветке или worktree; изменения доставляй через MR.
  Прямой push и force push в main запрещены.
- Обязательные ai-harness, отдельное согласование Requirements, Approve,
  ревью моделью и merge train не требуются. Issue создавай, когда он нужен
  для учёта работы, а не как предварительное разрешение на каждое действие.
- Слияние выполняй в пределах явного поручения оператора или действующего
  разрешения FirstMate на слияние; отсутствие Approve не расширяет полномочия.
- Перед сдачей выполни проверки, соответствующие изменению, и сообщи их
  фактический результат. Не выдавай пропущенные проверки за успешные.
- Секреты не публикуй. Перед разрушительными действиями обеспечь путь
  восстановления; чужую незавершённую работу сохраняй.
- Отвечай по-русски, кратко и по делу. Доступные действия выполняй сам.

## Договорённости с оператором

- ChattyMy в браузере под Playwright — только через выход `FOREIGN_STRICT`
  в Clash Verge (профиль ai/kvn-111). Chrome запускать с
  `--proxy-server=socks5://127.0.0.1:17891` (вход `foreign-shell` → группа
  `FOREIGN`); перед запуском проверить, что `FOREIGN` стоит на
  `FOREIGN_STRICT` (`/proxies/FOREIGN` в API mihomo, сокет
  `/tmp/verge/verge-mihomo.sock`), иначе не запускать. Источник:
  gitlab:ai/codexpro#2, оператор 2026-10-06 — «pw chrome ChattyMy надо в
  strict-foreign».
- Проект учебный, но код и документация — по высшим отраслевым стандартам:
  с учениками каждый аспект разбирается как с enterprise senior-инженерами.
  Источник: gitlab:ai/codexpro#2, оператор 2026-10-06 — «проект хоть и
  учебный, должен документироваться и реализовываться в соответсвии с самыми
  высокими отраслевыми стандартами, мы будем с учениками разбирать каждый
  аспект как будто с настоящими энтерпрайз сеньер инженерами».
- Автоматизация работы с ChattyMy — до разбора с учениками, только под предохранителями потом удалить (лимиты,
  паузы, выключенное по умолчанию, заглушки): каждый в коде помечается
  `#внимание-учебно-аналитический-предохранитель`. Места, где Claude

  оператор 2026-10-06 — «нужно предусмотреть автоматизацию запуска и создание
  новых чатов - но обязательно вставить предохранительные заглушки - отметь их
  в коде #внимание-учебно-аналитический-предохранитель»; «ограничено
  предохранителями: лимиты, паузы - обязательно!!! и даже присмотр процесс

  Источник: сессия Claude на GitHub `dinered/codexpro` (коммит 063e007),

- Все пользовательские ветки и теги GitLab `ai-company/codexpro` и GitHub
  `dinered/codexpro` согласуются скриптом CI `sync-github`: создание и
  fast-forward, без удаления и перезаписи истории. Конфликт любой ветки или тега
  останавливает план до push. Служебные refs, Issues/MR/CI/settings не входят
  в Git-синхронизацию (`docs/github-sync.md`).
  Активация отдельно после review и проверенного ручного apply; по умолчанию
  dry-run и выключенный gate. Расписание — каждые 180 минут, только из защищённого
  `main`; при push задание не запускается. Перед переключением между серверами
  дождись успешного apply для последних правок или попроси Maintainer запустить его.
  Исключение из «`main` только через MR»: согласованные правки с GitHub могут
  приходить fast-forward заданием синхронизации. Доступы/защита самим скриптом
  не меняются. Исторический срок PAT GitHub — 2027-10-01; актуальность проверяет
  оператор без передачи значения агенту. Источник: gitlab:ai-company/codexpro#4,
  поручение оператора 2026-10-24 «не main весь репо должен быть в синхроне».
